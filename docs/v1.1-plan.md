# Stride v1.1 — Coaching Tone Overhaul

**Goal:** Make Stride feel like a coach who thinks with you, not a project management setup wizard.

**Trigger:** Day 1 dogfooding revealed that onboarding feels corporate,
planning should happen immediately (not wait for Monday), and the agent
should propose goal decomposition rather than expecting users to arrive
with a task list.

**Scope:** 6 files changed, 0 new files, 0 data model changes, 0 new tools, 0 infra changes.

---

## Key Product Decisions

| Decision | Before (v1.0) | After (v1.1) |
|----------|---------------|--------------|
| When does planning happen? | Monday morning (user waits after onboarding) | See "Planning Model" below — depends on context |
| Who proposes tasks? | User ("What do you want to do this week?") | Stride proposes, user confirms ("Here's what I think makes sense...") |
| How many tasks in onboarding? | 1, then "anything else?" | 2-3, proposed by the agent based on goal decomposition |
| Where's the phase plan stored? | Nowhere | `project.description` — agent writes structured text |
| Goal progress in context? | No — agent only sees current cycle | Yes — days remaining, cycles completed, velocity |
| Conversation weekly reset? | Hard reset on planning day | Removed — 20-turn cap handles trimming naturally |
| Multi-question enforcement? | Prompt says "one at a time" | Stronger prompt + validator telemetry metric |
| Goal states? | All projects treated as active | Active (has cycle+tasks) vs Backlog (captured, not planned) |

---

## Planning Model — When Does Planning Happen?

Planning is not one-size-fits-all. There are **4 moments** planning can occur, each with different behavior:

### Moment 1: Onboarding (first goal ever)

**Always plan immediately.** The user's first experience must deliver full value:
goal → phases → this week's tasks → rhythm explanation. If they leave onboarding
with just a saved goal and no plan, they got nothing.

```
User: "I want to launch my portfolio"
Stride: [proposes phases, creates this week's tasks, sets up rhythm]
```

### Moment 2: New goal added mid-week (post-onboarding)

**Ask the user.** They might be capturing an idea, not ready to plan.

```
User: "I also want to start a YouTube channel"
Stride: "Got it — saved 'Start YouTube channel' as a goal.
         Want to break it down and plan now, or should I bring
         it up on your next planning day?"
```

- **"Now"** → full decomposition: phases, create cycle, create tasks
- **"Later" / "Monday" / no response** → `create_project` only, no cycle, no tasks.
  This goal sits in "backlog" until planning day.

The distinction between active and backlog is implicit — no new data model field needed:
- **Active** = project has an active work cycle (tasks exist for this week)
- **Backlog** = project exists but has no work cycle (captured, not planned)

`list_active_projects` already returns `active_cycle: null` for backlog goals.

### Moment 3: Planning day (Monday or user-configured)

This is the richest session. The scheduler sends the proactive message, and the
agent conversation handles the rest. The flow:

1. **Review active goals:** "Last week you finished 3 of 4 tasks on your portfolio."
2. **Surface backlog goals:** "You also have 'YouTube channel' saved — want to
   start planning that this week?"
3. **Plan each active goal:** Create new work cycle, propose tasks referencing
   the phase plan in `project.description`.
4. **Reprioritize:** "Which goals are the main focus this week?"

### Moment 4: On demand

User explicitly asks: "Let's break down my YouTube goal" or "Plan my week" →
Stride runs the full decomposition + planning flow.

### How this affects the context builder

The `_build_user_context` function splits projects into two sections:

```
Active goals:
- Portfolio (due June 1, 35 days away)
  Plan: Phase 1: Research. Phase 2: Content. Phase 3: Launch.
  This week: Wireframes [done], Logo [in_progress], Content [todo]

Backlog (saved, not yet planned):
- YouTube channel (no deadline)
- Learn Spanish (no deadline)
```

This gives the agent clear signal: active goals have tasks to work on,
backlog goals are waiting for the user to activate them.

### How this affects the scheduler

Monday planning message changes:

```python
# Before (v1.0):
"New week! Here are your active projects: ..."

# After (v1.1):
"New week! Last week you finished 3 of 4 portfolio tasks.
 You also have 'YouTube channel' saved — want to plan that too?"
```

### How this affects the prompt

The CAPACITY_LANGUAGE_ADDENDUM gets a new section:

```
NEW GOALS (post-onboarding):
When a user mentions a new goal AFTER onboarding:
- Save it immediately: call create_project with the name.
- Then ask: "Want to break this down and plan now, or should I bring it up
  on your next planning day?"
- If they want to plan now → full decomposition flow (phases, cycle, tasks).
- If they want to wait → leave it as a backlog goal. No cycle, no tasks.
- On planning day, surface all backlog goals and ask which to activate.

BACKLOG vs ACTIVE:
- A goal WITH an active work cycle = active (being worked on this week).
- A goal WITHOUT a work cycle = backlog (saved for later).
- The pre-loaded context shows both. Reference backlog goals on planning day.
- Never create a work cycle for a backlog goal unless the user asks for it.
```

## Change 2: Capacity Language & Goal Decomposition Addendum

**File:** `scrumbot-app/functions/sms/handler.py`
**What:** Rewrite `_CAPACITY_LANGUAGE_ADDENDUM`.

**New text:**

```python
_CAPACITY_LANGUAGE_ADDENDUM = """
CRITICAL — how you talk about workload:
- NEVER say "S", "M", "L", "XL", "small", "medium", "large", "points", "pts", or "story points".
- NEVER say "I'll mark that as M" or "That's an L task." The user must not see the sizing system.
- Always use time language: "a few hours", "a day or two", "most of the week", "more than a week".
- Talk about capacity in days: "You usually get about 3 good days of work done per week" (not "15 points").
- When a user is over-planned: "That's about 5 days of work for a 3-day week. What can wait?"
- The estimate and point system exists internally for tracking. Users must NEVER see any part of it.

GOAL DECOMPOSITION — how to break down a goal (used during onboarding AND on-demand planning):
When planning a goal (e.g. "launch my portfolio", "save $5K", "get 10 clients"):
1. Confirm it: restate it back to make sure you understand.
2. Ask for a deadline: "When do you want that done by?" If no deadline, suggest one
   together: "Let's aim for 6 weeks from now?"
3. Propose 2-3 phases: "I'd break that into: 1) [phase], 2) [phase], 3) [phase]. Sound right?"
4. Store the phases: call create_project with the phase plan in the description field, e.g.
   description="Phase 1: Research and pick template (week 1). Phase 2: Write all content (weeks 2-3). Phase 3: Go live and share (week 4)."
5. Focus on THIS WEEK: "Let's plan this week. For phase 1, I think these make sense:" then
   propose 2-3 concrete tasks and create them.
6. Never dump all phases as tasks. One week at a time. Future phases are in the plan, not the task list.

NEW GOALS — capture vs plan:
When a user mentions a new goal AFTER onboarding:
- Save it immediately: call create_project with the name (and deadline if they mention one).
- Then ask: "Want to break this down and plan now, or should I bring it up on your next
  planning day?"
- If they want to plan now → run the full decomposition flow above (phases, cycle, tasks).
- If they want to wait → leave it as a backlog goal. No cycle, no tasks yet.
- On planning day, surface all backlog goals: "You also have 'YouTube channel' saved —
  want to start planning that this week?"

BACKLOG vs ACTIVE GOALS:
- A goal WITH an active work cycle = active (being worked on this week).
- A goal WITHOUT a work cycle = backlog (saved, waiting to be planned).
- The pre-loaded context labels both clearly. Reference backlog goals on planning day.
- Never create a work cycle for a backlog goal unless the user explicitly asks to plan it.

MULTIPLE ACTIVE GOALS:
- Users can have multiple active goals at the same time. Each is a separate project.
- When planning or checking in, reference all active goals: "You've got two things going —
  the portfolio and the blog. What's the focus this week?"
- If a user mentions a new goal mid-conversation, create a new project. Don't merge it into
  an existing one unless they ask.

PLANNING DAY (Monday or user-configured):
- Review each active goal: last week's progress, this week's focus.
- Surface backlog goals: "You also have [X] and [Y] saved. Want to activate one of those?"
- For each active goal: create a new work cycle with tasks for the week. Reference the phase
  plan from the project description to pick the right focus.
- Let the user decide priorities: "Which goals are the main focus this week?"

WHEN THE WEEK IS ALREADY PLANNED (user already has tasks):
- If a user already has tasks for the week and texts you, don't re-plan. Help them with
  what they have — check in, update status, work through blockers.

HABITS — separate from goals:
- Habits are recurring practices: "Write 30 min daily", "Exercise 3x/week", "Read before bed".
- Use create_habit for these, NOT create_task.
- Habits have streaks. Celebrate milestones: "5 days in a row writing — nice!"
- In morning check-ins, mention both tasks and habits.
- In Friday reviews, include habit streaks: "You wrote 5 of 7 days this week."
- If a streak breaks, be encouraging: "Missed yesterday — want to get back on it today?"

FRIDAY REVIEWS — what to include:
- Tasks: X of Y done, name the ones that got done and the ones that didn't.
- Goal progress: reference the phase plan. "You're in Phase 1 of the portfolio.
  You've been at it for 2 weeks with 35 days until the deadline."
- Habits: streak summary for each habit.
- One pattern: something you notice (overcommitting, avoiding certain tasks, blockers recurring).
- One suggestion: something concrete to try next week.
"""
```

### 5a. Split projects into Active vs Backlog

Restructure the project loop to separate goals with active cycles from those without:

```python
# Inside _build_user_context, replace the current project display with:

active_goals = []
backlog_goals = []

for p in projects["projects"]:
    if p.get("active_cycle"):
        active_goals.append(p)
    else:
        backlog_goals.append(p)

if active_goals:
    lines.append("\nActive goals:")
    for p in active_goals:
        due = f" (due {p['target_date']})" if p.get("target_date") else ""
        lines.append(f"- {p['name']}{due}")

        # 5b: Phase plan from description
        if p.get("description"):
            lines.append(f"  Plan: {p['description']}")

        # 5c: Days remaining (import `from datetime import date` at top of file)
        if p.get("target_date"):
            try:
                target = date.fromisoformat(p["target_date"])
                days_left = (target - date.today()).days
                if days_left > 0:
                    lines.append(f"  Deadline: {days_left} days away")
                elif days_left == 0:
                    lines.append(f"  Deadline: TODAY")
                else:
                    lines.append(f"  Deadline: {abs(days_left)} days overdue")
            except ValueError:
                pass

        # Current cycle tasks (existing logic)
        cycle = p["active_cycle"]
        cycle_data = get_cycle_data(cycle_id=cycle["cycle_id"])
        if "error" not in cycle_data:
            for task in cycle_data.get("tasks", []):
                est = _ESTIMATE_LABELS.get(task.get("estimate_label", ""), "")
                est_str = f" ({est})" if est else ""
                lines.append(f"  - {task.get('title', '?')}{est_str} [{task.get('status', '?')}]")

        # 5d: Velocity history (overall progress)
        pace = get_pace_history(project_id=p["project_id"], num_cycles=5)
        if "error" not in pace and pace.get("cycle_records"):
            records = pace["cycle_records"]
            total_delivered = sum(r.get("delivered_points", 0) for r in records)
            total_planned = sum(r.get("planned_points", 0) for r in records)
            lines.append(f"  History: {len(records)} weeks completed, {total_delivered}/{total_planned} points delivered")

if backlog_goals:
    lines.append("\nBacklog (saved, not yet planned):")
    for p in backlog_goals:
        due = f" (due {p['target_date']})" if p.get("target_date") else "(no deadline)"
        desc = f" — {p['description']}" if p.get("description") else ""
        lines.append(f"- {p['name']} {due}{desc}")

if not active_goals and not backlog_goals and not is_new_user:
    lines.append("\nNo goals yet.")
```

### 7a. `_build_morning_reminder`

```python
def _build_morning_reminder(user_id: str) -> str:
    """Build morning reminder from live DynamoDB data. No Claude call."""
    projects = list_active_projects(user_id=user_id)
    if "error" in projects or not projects.get("projects"):
        return "Morning! What are you working on today?"

    lines = []
    task_count = 0
    total_active = 0

    for project in projects["projects"]:
        cycle = project.get("active_cycle")
        if not cycle:
            continue
        cycle_data = get_cycle_data(cycle_id=cycle["cycle_id"])
        if "error" in cycle_data:
            continue

        project_tasks = []
        for task in cycle_data.get("tasks", []):
            if task.get("status") in ("todo", "in_progress"):
                total_active += 1
                if task_count < MAX_TASKS_IN_REMINDER:
                    label = ESTIMATE_LABELS.get(task.get("estimate_label", ""), "")
                    estimate_str = f" ({label})" if label else ""
                    project_tasks.append(f"- {task.get('title', '?')}{estimate_str}")
                    task_count += 1

        if project_tasks:
            lines.append(f"{project['name']}:")
            lines.extend(project_tasks)

    if task_count == 0:
        return "Morning! No tasks set for this week yet. Want to plan some?"

    if total_active > MAX_TASKS_IN_REMINDER:
        lines.append(f"...and {total_active - MAX_TASKS_IN_REMINDER} more")

    lines.append("\nWhat are you tackling first?")
    return "Morning! Here's your plan:\n" + "\n".join(lines)
```

```python
            active_lines.append(f"- {p['name']}{due}")
            cycle_data = get_cycle_data(cycle_id=cycle["cycle_id"])
            if "error" not in cycle_data:
                for task in cycle_data.get("tasks", []):
                    total_count += 1
                    if task.get("status") == "done":
                        done_count += 1
        else:
            backlog_lines.append(p["name"])

    # Build header with last week's results
    if total_count > 0:
        header = f"New week! Last week you finished {done_count} of {total_count} tasks."
    else:
        header = "New week!"

    parts = [header]

    if active_lines:
        parts.append("Your goals:\n" + "\n".join(active_lines))

    # Surface backlog goals on planning day
    if backlog_lines:
        if len(backlog_lines) == 1:
            parts.append(f"You also have '{backlog_lines[0]}' saved — want to plan that too?")
        else:
            names = ", ".join(f"'{n}'" for n in backlog_lines)
            parts.append(f"You also have {names} saved — want to activate any of those?")

    parts.append("What's the focus this week?")
    return "\n".join(parts)
```

```python
def _build_review_prompt(user_id: str) -> str:
    projects = list_active_projects(user_id=user_id)
    if "error" in projects or not projects.get("projects"):

    done_count = 0

            total_count += 1
            if task.get("status") == "done":
                done_count += 1

    return (
        f"Week's done \u2014 you finished {done_count} of {total_count} tasks. "
        "How do you feel about this week?"
```
